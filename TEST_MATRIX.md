# Foundation test matrix

Generated from live paired-game declarations, actual browser e2e scenarios and retained strict pixel diagnostics. Run `npm run matrix:update` after adding a scenario or checkpoint; `npm run matrix:check` rejects drift. The previous port and its scenarios have been removed.

`npm run check` builds the Rust/WASM port and runs every live suite registered in [suites.mjs](tools/e2e/suites.mjs), retaining every exit status before failing. There is deliberately no CI: every agent runs `check:build` (assets, test policy, matrix synchronization, types and build), then the live suites its change touches and any suite whose driver, comparator or shared code it edits, comparing results against main before opening or merging a PR. Strict Clippy and formatting run separately through `npm run upkeep:check`; see [lint upkeep](docs/lint-upkeep.md). The paired gate gives a fresh original process and immutable production browser the same public tape after an explicit first-Title bootstrap boundary. The live gates check actual input delivery, seed readback and declared source-observable functional state across contrived and recorded OS-random cases. Every selected case executes; failures remain failures. Checked-in unit suites and the legacy Rust/WASM self-equality browser suite have been removed by user instruction; the only exception is the Antithesis deterministic simulation testing harness indexed below. Original GPU mask comparisons remain in the presentation suite.

All paired captures retain strict decoded-RGBA diagnostics. Their pixel failures remain failures in the report; tiny visual differences do not determine the default functional result. `--require-exact-pixels` opts into full-frame equality. The retained `verify:foundation` gate remains strict and optional, with its five known legacy full-frame failures. Earlier supplied-input physics/layout/combat diagnostic CLIs are now ignored research; their retained evidence remains separate from live browser gameplay acceptance.

## Antithesis deterministic simulation units

The only checked-in unit-level verification is the [Antithesis DST harness](docs/dst.md) in `engine/dst/` (owner-authorized exception; see [AGENTS.md](AGENTS.md)). It is an inner-loop regression tool, not a merge gate: neither `check:build` nor any pre-merge check runs it. `npm run test:dst` drives each registered unit with seeded entropy, checks every property after each step, replays the corpus tapes through the game unit and checks every game tape against the shipped `engine.wasm`; `--entropy antithesis` hands every decision to the Antithesis platform. Units and properties below are discovered from [the registry](engine/dst/src/units/mod.rs) and source; a run's report, not this list, is the outcome.
